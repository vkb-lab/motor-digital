# KOS UNICORN BUILDER OS DOCTRINE V1

Status: doutrina derivada do K-OS Origin Core Registry v1

## Premissa

K-OS é a extensão digital privada de Rogger.

Ele existe para transformar visão em empresas digitais executáveis, com IA no centro, GitHub como memória, Python como executor, Human Gate como proteção e ferramentas externas como braços subordinados.

## Ferramentas externas

Ferramentas externas não substituem o K-OS.

Elas entram como:

- conectores;
- toolbelts;
- bridges;
- geradores de ativos;
- ambientes de pesquisa;
- ambientes de desenvolvimento;
- executores assistidos.

Gmail, Google Toolbelt, Render, Codex, Canva, Gemini, Ollama e ferramentas futuras devem servir ao ciclo operacional do K-OS.

## Produtos e startups

Produtos, campanhas, automações, dashboards, apps e startups são saídas do K-OS.

O núcleo privado não deve ser exposto como produto público sem decisão explícita. A exposição pública deve priorizar os produtos criados, as provas, os ativos e os negócios derivados.

## Render

Render é observatório read-only/mobile.

Render pode mostrar status sanitizado, relatórios aprovados e cards de acompanhamento. Render não deve carregar runtime local, secrets, Gmail bruto, automação de navegador, publicação, deploy ou execução sensível.

## Aprendizado reutilizável

Cada projeto vira aprendizado reutilizável.

Cada aprendizado vira módulo.

Cada módulo acelera o próximo negócio.

O K-OS deve evitar tratar casos específicos como centro permanente do sistema. Hupmix, campanhas, produtos e clientes são matéria-prima para processos reutilizáveis.

## Regra de proteção

O núcleo K-OS permanece privado, soberano e local-first.

Ações de publicar, enviar, deletar, alterar produção, usar IA paga, automatizar navegador logado, mexer em credenciais ou acionar deploy exigem Human Gate.

## Regra de destino

O destino correto do K-OS é ser um Unicorn Builder OS privado:

- cockpit local enxuto;
- Operator Chat como frontdoor;
- Unified Command Cockpit como cockpit técnico;
- cloud read-only/mobile;
- ferramentas externas subordinadas;
- produtos e startups como saídas;
- memória e governança como ativos centrais.
